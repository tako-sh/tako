The goal is mesh delivery between Tako servers, bounded local replay with explicit ordering and deduplication, quiet SDK recovery, retained PostgreSQL support, and generated typed HTTP contracts. This report grounds that work in baseline `558135869072cd1e64e3dda08d3ee8663d786fe7` in `/workspace/tako`. It proposes bounded implementation slices for the parent to assign. It does not change the repository.

The main architectural change is to separate event identity, replay position, and delivery transport. Today a durable message's database ID does all three jobs implicitly. Local databases cannot provide a shared cursor across servers. PostgreSQL can provide ordered shared replay and already takes a transaction lock to make that safe. Mesh delivery needs its own event identity and retry rules while local replay needs an explicitly scoped cursor.

**Persistence, fanout, and ordering.**

SQLite is the production default. Its path is deployment-scoped, such as `apps/<app>/<environment>/data/tako/channels.sqlite`. A runtime `postgres_url` selects PostgreSQL with schema `tako_channels` and an app ID namespace. See [channels.rs](/workspace/tako/tako-server/src/channels.rs:7). The proxy and internal publisher maintain separate store caches. File-backed ephemeral hubs share a canonicalized database-path key so these independent objects still communicate within one process. Any new local replay service must preserve that sharing explicitly; replacing each `open_config` call with a fresh memory buffer would disconnect publishers from subscribers.

SQLite appends create/update metadata and insert the message in one transaction. The message ID is the database-wide `AUTOINCREMENT` integer serialized as a string. Reads filter by channel, seek above the cursor, order by ID ascending, and apply a caller-supplied limit. See [sqlite.rs](/workspace/tako/tako-channels/src/store/sqlite.rs:51) and [sqlite.rs](/workspace/tako/tako-channels/src/store/sqlite.rs:100). Same-file processes see each other's writes through polling. Separate server disks do not.

PostgreSQL stores `(app_id, channel)` metadata and messages with schema-wide `BIGSERIAL` IDs. Appends take `pg_advisory_xact_lock(hashtextextended(schema:app_id, 0))` before allocating the ID and committing. This serializes allocation and commit per app across servers. Without it, a subscriber could observe ID 11 before a transaction containing ID 10 committed and then skip 10 forever. Preserve this invariant in any PostgreSQL refactor. See [postgres.rs](/workspace/tako/tako-channels/src/store/postgres.rs:27). Shared PostgreSQL already delivers durable messages across server processes through head polling, without a mesh.

The durable transport drains pages of 100 records. `changes()` is a wakeup signal, not the event buffer. Each stream reads the database after a wakeup and drains full pages before sleeping. It subscribes before the replay read so a publication racing that read remains visible. See [store.rs](/workspace/tako/tako-channels/src/store.rs:145), [SSE loop](/workspace/tako/tako-server/src/proxy/service/channels.rs:148), and [WebSocket loop](/workspace/tako/tako-channels/src/websocket/serve.rs:91). Append does not immediately update these watch senders. The polling thread discovers changes, including external writers.

Ephemeral delivery uses a Tokio broadcast queue with capacity 64 per active channel. Messages have an empty `id`. SSE omits its `id:` line. There is no history when nobody subscribes, reconnect does not replay, and a lagged receiver skips evicted events. The last subscriber removes its channel sender. These are count bounds on queued events, not byte bounds or an aggregate server memory budget. See [ephemeral.rs](/workspace/tako/tako-channels/src/ephemeral.rs:11). PostgreSQL currently rejects both ephemeral publication and subscription in [store.rs](/workspace/tako/tako-channels/src/store.rs:288).

A repository search for mesh, gossip, memberlist, iroh, quinn, and peer-server delivery found no existing server mesh implementation. The peer-UID authorization in `tako-workflows` authenticates a local Unix socket, not another server. Mesh membership, transport, and authentication are new work. Do not describe the existing SQLite multi-process tests as cross-server mesh coverage.

Ordinary channel params are validated and passed to authorization, but do not partition the replay log. `Channel.publish` sends the declared name and lifecycle without bound params. SSE and WebSocket use `route.channel` for storage. Store and presence scopes explicitly hash canonical params. See [channels.ts](/workspace/tako/sdk/javascript/src/channels.ts:238), [proxy/service/channels.rs](/workspace/tako/tako-server/src/proxy/service/channels.rs:549), and [live_store.rs](/workspace/tako/tako-channels/src/live_store.rs:124). A mesh must preserve those distinctions. Treating every query param as a mesh topic key would silently change ordinary channel semantics.

**Cursor and expiry semantics.**

| Case | Baseline behavior | Consequence for the new work |
| --- | --- | --- |
| Cursor encoding | Signed `i64` text. SSE uses `Last-Event-ID`; WS uses `last_message_id`, with first-frame auth also supporting a resume ID. See [routing.rs](/workspace/tako/tako-channels/src/routing.rs:22). | Strings alone do not make the cursor opaque internally. Numeric assumptions also occur in server delivery loops and WebSocket parsing. |
| No supplied cursor | Resolve to the current retained maximum or metadata head. On a never-published stream this is `None`. | A new subscription starts live. It does not replay all retained history by default. |
| Supplied cursor | The lower bound is `oldest_retained_id - 1`, or the metadata head if all rows are gone. Unknown streams reject a supplied cursor. | The retained head is essential to distinguish old history from a never-published stream. |
| Cursor above the head | Accepted by `resolve_replay_cursor`; no upper bound is checked. | A cursor copied from another local database can suppress delivery until local IDs catch up. This is an inferred failure mode, not a runtime reproduction. |
| Expired cursor | SSE responds HTTP 410 before streaming. WS closes with 4410, `replay-too-old`. | Recovery belongs in transport state, outside application message payloads. |
| Replay age | Default 600,000 ms. Positive windows prune old rows on the cleanup worker. Zero disables age pruning in the Rust backends. | A time window alone does not bound count, bytes, stream cardinality, or metadata. |
| Inactivity | Default zero. Positive TTL prunes message rows after the last append or metadata sync. Metadata survives. | It does not close idle subscriptions. Some SDK comments imply otherwise. Pings and reads do not refresh database activity. |
| Connection lifetime | Default two hours. SSE ends normally; WS closes 1000 with `connection expired`. Keepalive default is 25 seconds. | Planned expiry should reconnect quietly. It is independent of replay eviction. |
| Expiry precision | Reads do not filter by wall-clock age. Cleanup runs about once a second plus work time. SQLite timestamps use `unixepoch() * 1000`. | Expiry is eventual and SQLite timestamps have one-second granularity. New hard retention bounds need checks in the read/append path. |

The cursor decision is centralized in [store.rs](/workspace/tako/tako-channels/src/store.rs:368). SQL pruning is in [sqlite.rs](/workspace/tako/tako-channels/src/store/sqlite.rs:199) and [postgres.rs](/workspace/tako/tako-channels/src/store/postgres.rs:193). The error mappings are in [proxy/service/channels.rs](/workspace/tako/tako-server/src/proxy/service/channels.rs:116) and [close_codes.rs](/workspace/tako/tako-channels/src/close_codes.rs:15).

Development is not cursor-equivalent to production. Ordinary dev SSE resolves `replay_cursor_async(channel, None)` without reading `Last-Event-ID`, and dev WebSocket passes `None` to the shared serve loop. Both therefore start at the current head on reconnect. See [dev_channels.rs](/workspace/tako/tako/src/bin/tako-dev-server/dev_channels.rs:287). Parent must wire the shared cursor contract into both dev paths and add resume/reset tests. This gap can hide a production stale-cursor loop during local testing.

First-frame WS parsing accepts either a string or integer resume ID and silently turns malformed values into `None`. When first-frame auth is used, its valid ID takes precedence over the query cursor. See [websocket.rs](/workspace/tako/tako-channels/src/websocket.rs:199) and [ws.rs](/workspace/tako/tako-server/src/proxy/service/channels/ws.rs:152). Include both parsers and their precedence in the cursor migration; updating only the URL parser is incomplete.

Two further cursor gaps matter. IDs are shared across channels, so `oldest - 1` can conservatively reject a cursor even when intervening IDs belonged only to other channels. More seriously for a bounded replay design, `read_after` does not revalidate the replay floor while a subscription is running. A slow connection can silently skip rows pruned between pages. These are source-derived risks. Add behavioral tests before choosing the new reset policy.

Lifecycle wire semantics also differ by language. Rust accepts zero replay age and then disables pruning. Go's `withDefaults` replaces zero with ten minutes and omits zero on serialization. Go permits selected nonzero lifecycle overrides in an authorization grant. JavaScript authorization returns definition lifecycle plus the subject and ignores grant lifecycle overrides. Compare [internal/channels.go](/workspace/tako/internal/channels.go:43), [internal/channels.go](/workspace/tako/internal/channels.go:288), and [channels.ts](/workspace/tako/sdk/javascript/src/channels.ts:428). Generated contracts should make omitted, zero, finite, and invalid values explicit instead of perpetuating this drift.

**SDK and Store recovery.**

The JavaScript SSE reader delegates parsing and reconnect header maintenance to `@microsoft/fetch-event-source`. It tracks a public `lastEventId`, forwards every nonempty frame as a `MessageEvent`, and uses exponential backoff with jitter. Every non-2xx response is converted into the same generic error. Clean EOF with retry enabled deliberately throws `SSE stream disconnected; reconnecting.` Its error handler invokes `onError` and dispatches an `ErrorEvent` before retrying. There is no special HTTP 410 reset, terminal auth classification, or event deduplication. See [sse-reader.ts](/workspace/tako/sdk/javascript/src/channels/sse-reader.ts:132).

Inference from that control flow: an expired SSE cursor is retried unchanged and can remain in a 410 loop. Changing only the reader's public `lastEventId` would not prove recovery; the active library request headers also need clearing or a fresh request lifetime. Test the actual next request header.

`Channel.connect()` itself does not reconnect. `useChannel` reconnects WebSockets, remembers the last received ID, and appends all decoded JSON into a 500-message UI buffer. It does not deduplicate, classify close codes, validate a business-message envelope, or clear the resume ref on a channel change. The WS close handler ignores the close event. Both ordinary auth rejection and stale replay therefore reach the same retry loop. The effect keys are name, transport, and serialized params, not the whole credential/origin identity. See [react.ts](/workspace/tako/sdk/javascript/src/react.ts:129). These are precise places for recovery and identity tests. The 500-message UI cap is unrelated to server replay retention.

There is no evidence that the baseline injects synthetic error objects into the business message list. It exposes transport errors on error callbacks and hook state. The requirement should preserve that distinction while removing expected recovery noise. Do not implement cursor-reset messages as ordinary `{type, data}` messages: `handleIncoming` currently accepts any parsed JSON and would deliver them to business handlers.

Stores already avoid client cursor replay. Each connection registers for changes, captures the current head, then sends `tako.store.ready`. Clients reload after ready and after `tako.store.invalidate`. The server ignores the client's `Last-Event-ID`. Invalidations contain no data or replay ID, and Store WebSocket/client publication is rejected. This is a snapshot invalidation protocol, not replay of intermediate database states. See [live_store.rs](/workspace/tako/tako-channels/src/live_store.rs:360) and [PROTOCOL.md](/workspace/tako/PROTOCOL.md:79).

Store publication scopes are canonical hashes of the reserved channel name and validated params. The trusted socket command supplies `scopeParams`; the server removes that metadata before emitting notifications. See [live_store.rs](/workspace/tako/tako-channels/src/live_store.rs:152). JavaScript, Go, and Rust already produce that command. JavaScript sends no lifecycle in `defineStore.invalidate`, Go includes one, and Rust sends just type/data/scopeParams. Do not require optional lifecycle fields when introducing a typed command. See [define.ts](/workspace/tako/sdk/javascript/src/stores/define.ts:143), [store_socket.go](/workspace/tako/internal/store_socket.go:16), and [stores.rs](/workspace/tako/sdk/rust/src/stores.rs:362).

The Store client starts an HTTP load promptly, reloads after ready, and coalesces invalidations through `dirty` and `pending`. Generation counters and aborts fence old responses. Terminal HTTP failures stop the stream and purge cached data. Recoverable SSE failures currently set `offline` or `error`, attach an Error, and mark the snapshot stale. See [client.ts](/workspace/tako/sdk/javascript/src/stores/client.ts:262), [client.ts](/workspace/tako/sdk/javascript/src/stores/client.ts:337), and [client.ts](/workspace/tako/sdk/javascript/src/stores/client.ts:516). Quiet recovery must still clear `streamReady` and mark data stale. Merely suppressing the error callback would leave freshness incorrect.

Store offline persistence is a separate bounded cache of previously authorized HTTP snapshots. Default IndexedDB limits are 1 MiB per entry, 64 entries, 16 MiB total, and seven days maximum age. Persistence requires explicit cache scope and backend policy. Runtime identity includes credentials, while persisted identity does not store them. Logout, cache version changes, and expiry invalidate snapshots. See [cache.ts](/workspace/tako/sdk/javascript/src/stores/cache.ts:19) and [client.ts](/workspace/tako/sdk/javascript/src/stores/client.ts:470). Preserve these safeguards during transport recovery changes.

The Go and Rust SDKs in this baseline provide Store definitions, loaders, authorization endpoints, and invalidation publishers. They do not have browser-style channel replay/reconnect clients. Rust exports presence and Store APIs, not a general channel consumer. Go exposes channel registries and Store publishers. Do not assign fictional Go/Rust reconnect loops. Their work is wire types, registry/lifecycle parity, HTTP contract definitions, and command serialization. See [Rust SDK](/workspace/tako/sdk/rust/src/lib.rs:1), [Go channel API](/workspace/tako/channels.go:1), and [Go Store API](/workspace/tako/store.go:1).

**What the generator actually generates.**

The existing JavaScript generators produce declaration fragments `TakoChannels` and `TakoStores`. They discover flat directories, dynamically import each default export, reject duplicates and nested directories, then refer to `InferChannel<typeof import(...)>` or `InferStore<typeof import(...)>`. Store discovery does not call loaders or authorization callbacks, but dynamic module import can still execute top-level application code. See [gen-channel-types.ts](/workspace/tako/sdk/javascript/bin/gen-channel-types.ts:6), [gen-store-types.ts](/workspace/tako/sdk/javascript/bin/gen-store-types.ts:7), and [discovery.ts](/workspace/tako/sdk/javascript/src/channels/discovery.ts:14).

Channel message typing is supplied through `$messageTypes`, a type-only operation, rather than a serializable message schema. Generated declarations do not create a runtime response validator or a method/path/request/response HTTP contract. `TakoStores` is consumed by the typed React Store hook. A source search found no corresponding `TakoChannels` lookup in the `useChannel` overloads; the channel exports themselves provide typed publication. See [define.ts](/workspace/tako/sdk/javascript/src/channels/define.ts:114), [index.ts](/workspace/tako/sdk/javascript/src/index.ts:171), and [react/store.ts](/workspace/tako/sdk/javascript/src/react/store.ts:12).

The Rust CLI combines generator output with secrets, storage, and environment declarations in `tako.d.ts`. It prefers the repository script and falls back to the installed package binary. Both helpers silently return no generated types when the codegen executable is not found. The Store generator accepts the actual declaration directory to compute import paths. The channel generator hardcodes `./channels/<stem>`, even though the CLI can preserve an existing declaration outside the app root. That asymmetry needs a regression fixture. See [js.rs](/workspace/tako/tako/src/build/js.rs:405), [js.rs](/workspace/tako/tako/src/build/js.rs:447), and [js.rs](/workspace/tako/tako/src/build/js.rs:497).

`tako generate` dispatches JavaScript declaration/scaffold generation or Go secret accessor generation. There is no Rust HTTP contract generation branch here. General application handlers are not introspected; for example the Go endpoint wrapper passes public requests straight to the user's `http.Handler`. See [codegen.rs](/workspace/tako/tako/src/commands/codegen.rs:26) and [endpoint.go](/workspace/tako/internal/endpoint.go:51).

Recommendation: treat generated typed HTTP contracts as explicit operation definitions with method, path, request, and response typing. Start with the platform's channel/Store HTTP DTOs and a declared application operation. Do not claim arbitrary framework routes can be inferred from existing channel metadata. Cross-language generation requires a serializable contract source or manifest; a TypeScript-only phantom message map cannot describe Rust/Go response types.

**Recommended target invariants.**

These are design recommendations, not baseline capabilities.

1. Define a deployed-app scope, stream key, stable event ID, and replay cursor as separate types. For mesh events, an origin ID, boot epoch, and monotonic publication sequence can form the stable identity. A local replay cursor includes the receiving server/store epoch and its local sequence. PostgreSQL keeps its shared committed sequence behind its backend cursor representation. JS carries cursors as strings and never compares them as floating-point numbers.
2. Guarantee one append order within each local replay log and ordered delivery from each origin within an epoch. Independent origins can interleave differently on different servers. Do not promise a global total order for the local mesh mode. Retain PostgreSQL when a shared durable order is required. A globally ordered local mode would need a sequencing/ownership protocol and is a separate project.
3. Bound replay by count, encoded bytes, and age, with an aggregate app/server budget and a stream-cardinality limit. Bound peer queues, dedup state, reorder buffers, and expired-stream metadata too. An in-memory SQLite database and a time window alone do not meet this requirement. Expiration and eviction update an explicit replay floor. Reopening an evicted stream uses a new epoch so an old cursor cannot masquerade as current history.
4. Deduplicate replicated event IDs before local append and fanout. Preserve IDs across mesh retries and forwarding. Do not discard every sequence below the largest seen value unless per-origin ordered admission is enforced. Bound reorder waiting; a missing event beyond the recovery window must lead to an explicit transport reset. Define duplicate suppression only within a stated retention/epoch horizon, not as unbounded exactly-once delivery.
5. Distinguish transient no-replay publication from bounded replay publication. Ephemeral channels remain live-only unless the protocol deliberately changes their meaning. Their delivery can use mesh without writing PostgreSQL message rows. A generic mesh ACK must mean local acceptance or a named peer acknowledgment, not durable cluster-wide commit.
6. Validate the cursor epoch, stream scope, lower floor, and upper head atomically with the replay read. Subscribe and capture the head without a replay/live gap. Detect eviction while an existing reader is behind, not only at handshake. Never reuse a cursor from a different local server as a numeric lower bound.
7. Use a transport control event or state callback for reconnect, reset, and terminal failures. Business `onMessage`, message arrays, and typed payload unions receive application data only. For an unrecoverable cursor, clear it and start a fresh live connection quietly. Generic channel consumers may need an optional out-of-band resync notification; quiet recovery cannot reconstruct lost business events.
8. Preserve Store ready-then-load recovery. On mesh loss or queue overflow, even a healthy client-to-server SSE connection may have missed remote invalidations. Trigger a Store resync or restart the notification stream on mesh recovery so ready forces a reload. Waiting for the browser connection to happen to reconnect is insufficient.
9. Preserve PostgreSQL as a persistence backend with its commit-order lock, app scoping, retained head, and polling fallback. Mesh may carry wakeup hints for durable PostgreSQL rows. A receiver must not reinsert every mesh hint into the shared database. Ephemeral mesh data is a separate path.
10. Adopt protocol v0 changes in producers and consumers together, as [AGENTS.md](/workspace/tako/AGENTS.md:3) allows. Define finite/zero/omitted lifecycle semantics and typed reset/error codes once. Avoid compatibility branches that preserve the old numeric-only cursor assumption in one language.
