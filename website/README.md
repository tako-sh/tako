# Tako Website

Astro builds the homepage and blog. Blume builds the documentation. The combined static site deploys through Cloudflare Workers static assets, with no Worker script or upstream documentation service.

## Routes

- `/`: landing page
- `/docs` and `/docs/*`: documentation, local search, and agent endpoints built by Blume
- `/install.sh`: permanent redirect to the GitHub-hosted CLI installer
- `/install-server.sh` and `/server-install.sh`: permanent redirects to the server installer
- `/blog/{slug}`: HTML blog post
- `/blog/{slug}.md` and `/blog/{slug}.json`: authored Markdown and structured blog data
- `/skills.md`: index of canonical SDK and workflow skills

Cloudflare serves extensionless HTML without trailing slashes. Existing trailing-slash links redirect to the canonical URL. Installer redirects live in `public/_redirects`; shared discovery headers live in `public/_headers`.

## Documentation

Use `commands/sync-docs.md` to keep documentation in sync with implementation changes. Optionally provide a feature, paths, or commit range to focus the work. Edit flat `.md` files in `docs/`, using `.mdx` when interactive components such as code tabs are needed, and keep `title` and `description` frontmatter. The CLI embeds those same files at build time, so keep them readable without a website renderer.

Navigation lives in `src/config/docs-navigation.ts`, shared by Blume and the root agent index. `documentation/blume.config.ts` configures rendering, branding, search, and the `/docs` deployment base. Internal documentation links are relative to the docs root, such as `/quickstart`; Blume prefixes them with `/docs` in generated HTML and Markdown.

Coding agents are the primary documentation readers. The home page routes tasks to focused topics; the root `llms.txt` links directly to Markdown. Navigation separates Get started, Framework guides, Docker, Primitives, Deploy and operate, and Reference. Framework guides cover the shipped JavaScript, Go, and Rust integrations. Docker covers image configuration, language-specific Dockerfiles, and workflow containers. Primitives cover Secrets, Storage, Images, Cache, Channels, Presence, Stores, and Workflows. Use MDX with named `CodeGroup` fences for equivalent language examples; Blume renders tabs and exports every variant as Markdown. CLI-bundled source retains the labeled fences. Keep command/config details in references and SDK depth in canonical skills. MCP reads page titles from frontmatter; skill topics use their H1 headings. Feature-request URLs redirect to GitHub issues. Preserve existing anchors when moving a section into a focused topic.

Documentation uses the website's fixed dark theme, with no color-mode toggle. Colors and component details live in `documentation/theme.css`. The config shares `SNIPPET_THEME` from `src/config/snippet-theme.ts` with the homepage and blog. Light tokens remain available for Blume's print styling.

Blume discovers browser icons by filename. `documentation/public/icon.svg` and `apple-touch-icon.png` symlink to the main site's assets, keeping browser tabs and iOS home-screen icons consistent without duplicate artwork. Generated documentation OG cards use the same logo, palette, and JetBrains Mono font.

The docs shell matches the main site's `clamp(20px, 5vw, 80px)` outer gutter and logo dimensions. Its article keeps a readable maximum width, with narrower desktop side rails and a mobile drawer button on the right.

`bun run build` synchronizes SDK skills, builds Astro into `dist/`, builds Blume into `documentation/dist/`, and runs `scripts/build-docs.ts` to copy the docs into `dist/docs/`. The script adds Context7 discovery information to generated HTML and Markdown and merges Blume's header and redirect rules into the deployment root. Generated runtimes and build output are ignored by Git.

## Agent Discovery and Context7

Use `commands/sync-agents.md` for agent-support maintenance.

- `/llms.txt` combines the shared documentation navigation, page frontmatter, blog Markdown links, and project guidance from `src/utils/llms.ts`.
- `/docs/llms.txt` and `/docs/llms-full.txt` are generated by Blume, alongside `.md` mirrors, a JSON API, and agent discovery manifests.
- `/agent-readability.json` describes the complete site. `/.well-known/api-catalog`, `/.well-known/ai-catalog.json`, and `/.well-known/ard.json` expose Blume's catalogs at the domain root. The build copies these from the documentation output and advertises them through HTML and HTTP links.
- Context7 Ask uses `src/config/context7-ask.ts` for verification, the hidden HTML note, Markdown Search sections, and the search response header. These are included in the static build. After deployment, use **Check again** in the Context7 Ask dashboard to verify the site.
- The reader-facing chat widget lives in `src/components/Context7Widget.astro`, mounted through Blume's `PageFooter` override. It uses the `/tako-sh/tako` Context7 library and persists across Astro client navigation. It is independent of the agent-facing Ask endpoint.
- `/skills.md` and `/.well-known/agent-skills/` publish canonical files from `sdk/javascript/skills/`, regenerated by `scripts/sync-agent-skills.ts`.
- Blume also publishes those same canonical skills under `/docs/.well-known/agent-skills/`; its catalog uses their generated URLs and hashes.
- `public/.well-known/http-message-signatures-directory` publishes the Web Bot Auth public keys.
- Blog posts expose `.md` and `.json` endpoints. `src/components/layout/BaseScripts.astro` also registers feature-detected WebMCP tools.

Blume's discoverability configuration enables canonical metadata, branded Open Graph cards, Git-derived publication/modification dates, structured page data, a sitemap, richer LLM guidance, Markdown mirrors, the static JSON API, catalogs, and browser WebMCP tools. Shared entity IDs in `src/config/site-identity.ts` connect documentation pages to the homepage's website and publisher. The root sitemap includes the documentation sitemap; the existing blog RSS feed is advertised throughout the site. Root `robots.txt` remains the crawl-policy source.

Hosted MCP, HTTP search, and `Accept: text/markdown` negotiation require a server and are disabled in this static deployment. Explicit `.md` URLs work. DNS-AID would require publishing DNS records separately; no DNS changes are part of the build. The existing Web Bot Auth public-key directory remains available.

For the Context7 library, include `website/docs`, `sdk/javascript`, `sdk/go`, and `sdk/rust`, plus the root Go HTTP SDK sources: `tako.go`, `presence.go`, `store.go`, and `internal/`. The `sdk/go` directory is the separate workflow SDK. Exclude `examples` and `sdk/javascript/skills`, plus maintainer instructions, plans, and internal contracts, in the library settings.

## Local Development

Install dependencies from the repository root:

```bash
bun install
```

Run these in separate terminals:

```bash
bun run --cwd website docs:dev
bun run --cwd website dev
```

Open the Astro URL, normally `http://localhost:4321`. Its development server proxies `/docs` to Blume on port 4322, including documentation assets and search. Build-time Context7 HTML and Markdown additions are verified in the combined production preview.

To preview the complete production build with Cloudflare's redirects and headers:

```bash
bun run --cwd website build
bun run --cwd website preview
```

## Checks and Deployment

```bash
just check website
bun run --cwd website verify
```

The check typechecks Astro and Blume, validates documentation links and anchors, builds both sites, and checks all local HTML links. The verifier checks every documentation page, canonical URLs, Markdown frontmatter, Context7 integration, shared structured-data identities, social-card dimensions, static API coverage, advertised discovery resources, and canonical skill contents and hashes. CI runs these checks for website changes.

Deploy the verified output with:

```bash
bun run --cwd website deploy
```

## Blog Images and Icons

Blog hero sources live in `src/assets/blog/` as PNG files referenced by frontmatter ID. Astro optimizes them during the build and emits OG images under `dist/assets/blog/og/`.

UI icons use `@hugeicons/core-free-icons`, rendered by `src/components/HugeIcon.astro`. Decorative icons use `aria-hidden="true"` and `focusable="false"`.
