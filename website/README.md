# Tako Website

Astro static site deployed with Cloudflare Workers static assets. The Worker proxies `/docs` and `/docs/*` to Docs7.

## Routes

- `/`: static landing page
- `/docs/` and `/docs/*`: documentation served by Docs7 from `docs/`
- `/install.sh`: `301` redirect to GitHub-hosted POSIX `sh` installer script for `tako`
- `/install-server.sh`: `301` redirect to GitHub-hosted POSIX `sh` installer script for `tako-server`
- `/server-install.sh`: alias for `/install-server.sh` (same redirect target)
- `/blog/{slug}/`: HTML blog post
- `/blog/{slug}.md`: authored Markdown for a blog post
- `/blog/{slug}.json`: structured blog post data, including frontmatter, headings, and Markdown
- `/skills.md`: Markdown index of published Agent Skills for agents, including the skills.sh install command

Installer redirects are configured in `public/_redirects` (Cloudflare static assets redirects). Agent-discovery `Link` response headers (RFC 8288) are configured in `public/_headers`.

## Agent Discovery

Use `commands/sync-agents.md` from the repository root for the complete agent-support upkeep workflow.

- `/llms.txt` is generated by Astro from the Docs7 navigation in `docs/docs.json`, page titles/descriptions in `docs/**/*.md`, and the blog collection. Docs stay in navigation order; blog links use their Markdown endpoints and appear newest first under Optional. Shared product guidance and project links live in `src/utils/llms.ts`. Change these sources and rebuild instead of editing `dist/llms.txt`.
- `/docs/llms.txt` and `/docs/llms-full.txt` are generated and served by Docs7 through the docs proxy. The root index links to both.

- Context7 Ask uses `src/config/context7-ask.ts` for the endpoint and discovery copy. `BaseLayout.astro` renders its verification tag and hidden note in static HTML. The Worker adds them to Docs7 HTML responses and prepends the Search section to Docs7 Markdown responses.
- `/llms.txt`, `/skills.md`, blog Markdown endpoints, and the Docs7 `llms.txt` and `llms-full.txt` responses include the Search section. The Astro build adds the search `Link` header to `dist/_headers`; the Worker adds it to proxied docs responses. After deploying, use **Check again** in the Context7 Ask dashboard to verify the site.
- `_headers` — RFC 8288 `Link` headers pointing agents at docs, `llms.txt`, `skills.md`, and the sitemap
- `public/.well-known/http-message-signatures-directory` — Web Bot Auth JWKS (Ed25519 public key)
- `public/.well-known/agent-skills/` — Agent Skills Discovery v0.2.0 index + `SKILL.md` copies; regenerated from `sdk/javascript/skills/` by `scripts/sync-agent-skills.ts` on each build
- `/skills.md` — Markdown index that points agents at the structured Agent Skills index, skills.sh install command, and each published `SKILL.md`
- Blog posts expose explicit `.md` and `.json` endpoints from `src/pages/blog/`.
- WebMCP tools (`navigator.modelContext.provideContext`) registered in `src/components/layout/BaseScripts.astro` — `navigateToDocs`, `searchDocs`, `getStartedCommand`, `getInstallCommand`. Feature-detected, silently no-ops in browsers without the API.

## Run Locally

```bash
bun install
bun run --cwd website dev
```

This previews the landing page and blog. Preview documentation with the Docs7 command below; `/docs` is proxied by the deployed Worker.

```

bun run --cwd website build

```

## Checks

```bash
bun run --cwd website check
bun run --cwd website build
bun run --cwd website verify
```

Website source, Astro configuration, and browser scripts use TypeScript. `check` generates Cloudflare runtime types under the ignored `.astro/` directory and checks the Worker separately from Astro's browser types. `verify` checks generated HTML, Markdown, Context7 discovery headers, Docs7 page coverage in the root `llms.txt`, and published skill contents/hashes. CI runs it after building.

## Docs7

The Markdown guides and `docs.json` in `docs/` are the Docs7 source. Astro builds the landing page and blog; Docs7 renders the documentation. Use paths relative to the docs root for internal links, such as `/quickstart/`. Page titles and descriptions belong in frontmatter; Docs7 supplies the heading.

Preview Docs7 from the repository root:

```bash
npx @upstash/docs7 dev website/docs
```

In the Docs7 dashboard for `tako-sh/tako`, use `master` as the production branch and `website/docs` as the docs path. Publishing requires `docs.json` to be on that branch. The custom URL is `tako.sh/docs`, with `https://tako-sh.docs7.io/docs` as the proxy origin. `src/worker.ts` forwards the docs path, query, method, body, and response headers and preserves redirects. The `run_worker_first` rules in `wrangler.jsonc` send docs requests to the proxy before looking up Astro assets. Other paths use the website's static assets. Deploy with the website's normal build and deploy commands.

The Context7 library includes `website/docs`, `sdk/javascript`, `sdk/go`, and `sdk/rust`. Exclude `examples` and `sdk/javascript/skills`. Root Markdown files are always included, so exclude maintainer instructions, plans, and internal contracts by filename in the library settings.

## Blog Images

Blog hero sources live in `src/assets/blog/` as PNG files referenced by the `image` frontmatter ID. `bun run build` optimizes those images with Astro and emits compressed OG PNG endpoint files in `dist/assets/blog/og/`.

## Icons

UI icons use the official `@hugeicons/core-free-icons` package. Import icons from their individual package paths and render them with `src/components/HugeIcon.astro`, with `aria-hidden="true"` and `focusable="false"` for decorative icons.
