`tako-network` owns validated device identities, public enrollment proofs, local key storage, and policy over a trusted server's registry snapshot. It does not implement SQL, replication, network commands, TLS, SSH sessions, or HTTP authorization adapters.

Use `NetworkId::random()` once. An immutable `NetworkDescriptor` names that network and its initial administrator. Bootstrap the matching device through `RegistrySnapshot::approve` with `approved_by = None` and `network_admin = true`. Its descriptor grants the bootstrap exception only in an empty registry. Add one server through an explicit server-admin approval; additional servers do not change the network identity or existing addresses.

`LocalDeviceKeys` generates separate Ed25519 SSH and X25519 WireGuard keys. An enrollment request can omit its target network. Its SSHSIG binds version, optional network, device kind, request ID, optional device ID, expiry, name, and both keys through fixed v1 framing. `Member` binds the unchanged request to the selected network. Device IDs hash a versioned domain, network ID, device kind, canonical SSH wire bytes, and WG bytes. Names and comments are not identity inputs; public SSH keys must be comment-free.

An SSH signature binds the WG public key but does not prove possession of its private key. The server calls `WgChallenge::begin`; the new laptop calls `answer_challenge`; the server consumes `PendingWgChallenge::verify`. The challenge expires within 300 seconds and binds the request, network, device, nonce, and ephemeral key. OpenSSL performs X25519 and HMAC-SHA256, and compares responses in constant time. `VerifiedEnrollment` cannot be deserialized or constructed by a caller. The caller authenticates the challenge channel and retains the single-use server state. A file-only enrollment needs a challenge/response exchange before admission; the request file alone is insufficient.

`RegistrySnapshot::approve(verified, Approval)` returns an immutable `Member`; it does not write it. The trusted server serializes authorization and commit, checks stable command IDs, persists accepted records, and reconciles OS state. Only trusted agents can import `Member`, `Revocation`, and `Ack` records. Do not expose their deserializers as a client mutation API. `wg_verified` and `independent_admin` are trusted server assertions, not applicant claims. Unverified key claims do not participate in effective membership or collision detection. Conflicting verified records and address collisions fail closed; identical duplicate delivery is safe.

`Permissions::default()` grants no network administration, server administration, SSH user, or deployment access. `can_deploy` requires an exact canonical `app/env`. A network administrator can delegate its scopes and SSH user; granting a different SSH user, arbitrary deployment scopes, or server membership requires server administration too. Child membership cannot outlive the parent. Server administration does not itself make a member a deployment principal; deployments still require an explicit scope. Parent adapters must enforce the result on every RPC, upload, log, secret, and deployment operation.

Ordinary admissions retain the approving device as a dependency. `effective_members(now)` denies missing ancestors, cycles, revoked ancestors, expired authority, and delegation escalation. Revoking an admin also denies admissions it approved on a stale replica. Admission and revocation are not globally ordered; a partitioned server may still accept a denial from an already-revoked admin. Accepted denials remain permanent after convergence, even when their actor is no longer effective.

Independent recovery authority has a separate entry point. `approve_independent_admin` requires a server adapter to authenticate a local operator independently of network device grants, for example through a protected root console. It requires `independent_admin = true`, `approved_by = None`, and both admin permissions. An ordinary admin RPC cannot invoke this operation. This separation prevents a stale revoked admin from minting independent successors. Operator-authenticated recovery works even when every network admin has been revoked, but cannot revive banned keys. The operator's audit log records who authorized the independent root.

Before retiring the first laptop, enroll an independent recovery admin and account for its ordinary descendants, including servers. A normal delegated server admission also depends on its approving device. A trusted server that must survive that device's retirement needs explicit independent operator admission with both admin capabilities. This is appropriate only for the trusted server agent, which already has registry write authority. There is no implicit promotion or ancestry editing. Existing immutable records cannot silently become independent; use fresh keys for replacement. Routine server retirement denies that server's identity, not admissions it merely wrote for an administrator.

`plan_revocation` captures the target device and both key fingerprints, plus all known enforcement servers. Negative facts override stale membership and new identities that reuse either key. Persist the returned record before reporting durable acceptance. Apply WG removal, future SSH/login denial, session cancellation, and management denial before recording an `Ack`. This crate cannot perform or attest OS enforcement. The parent bounds input sizes without discarding historical revocations, owns synchronization with queued privileged work and distinguishes durable receipt from completed enforcement.

`revocation_progress` requires fresh authenticated readiness reports from reachable, successfully reconciled server agents. Remove a boot entry after failed enforcement or loss of readiness. It reports every captured server and later-admitted server without a matching current ACK as pending. Old ACKs, absent members, and server retirement never imply fencing. Restarts, failed enforcement, offline servers, and restore uncertainty remain visible. The parent must gate a newly admitted server on synchronization and reconciliation. No function claims that a local snapshot is globally current.

The IPv6 derivation uses `fd` plus 40 bits of SHA-256 over `tako-network-prefix-v1\0 || network_id`, then 80 bits over `tako-network-host-v1\0 || network_id || wg_public_key`. Inputs are raw bytes. `Member::allowed_ip()` returns only an exact `/128`. There is no allocation counter, central allocator, or primary server.

`NetworkPublicProfile` contains only the public request, registry snapshot, and exact effective server pins. `validate_for` checks local public-key ownership, admitted request identity, and server-pin consistency. It cannot authenticate a file's origin. Import only through authenticated transfer or a pinned server connection; a digest or certificate carried inside the same untrusted file is not a trust anchor. An absent HTTPS pin requires ordinary trusted certificate validation, never disabled verification. The parent must also bind import to the user's intended network when an unbound request was used.

On Unix, `save_new` traverses directories without symlinks, requires a caller-owned parent directory without group/other write permission, writes a fresh 0600 temporary file, fsyncs it, publishes with a non-replacing hard link, removes the temporary name, and fsyncs the directory. Existing files and symlinks cannot be replaced. `load` checks file type, ownership, exact permissions, link count, and a bounded file size. A crash between publication and temporary-link removal fails closed until the operator removes the orphan temporary link. A reported I/O failure after publication requires inspecting the path rather than overwriting it. Non-Unix platforms return `UnsupportedPlatform` until a secure platform store is supplied.

Private key objects have no `Debug` or serde implementation. Temporary serialized secrets use zeroizing buffers. `wireguard_private_key` explicitly exports a zeroizing value only for a trusted WireGuard configurator. Never put it in a public profile, CLI log, app environment, or process argument. `sign` permits SSHSIG authentication without exporting the SSH private key.

Run `cargo test -p tako-network --offline` and `cargo clippy -p tako-network --all-targets --offline -- -D warnings`. The tests cover real cryptographic proofs and Unix persistence, plus policy failures and partition scenarios over snapshots. They do not prove Corrosion convergence, OS WireGuard enforcement, SSH session termination, or integrated CLI/server behavior; the parent owns those checks.
