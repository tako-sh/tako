`tako-network` owns validated device identities, public enrollment proofs, local key storage, and policy over a trusted server's registry snapshot. It does not implement SQL, replication, network commands, TLS, SSH sessions, or HTTP authorization adapters.

Use `NetworkId::random()` once. An immutable `NetworkDescriptor` names that network and its initial administrator. Bootstrap the matching device through `RegistrySnapshot::approve` with `approved_by = None` and full permissions. Its descriptor grants the bootstrap exception only in an empty registry. Add one server through an approval by a full member; additional servers do not change the network identity or existing addresses.

`LocalDeviceKeys` generates separate Ed25519 SSH and X25519 WireGuard keys. An enrollment request can omit its target network. Its SSHSIG binds version, optional network, device kind, request ID, optional device ID, expiry, name, and both keys through fixed v1 framing. `Member` binds the unchanged request to the selected network. Device IDs hash a versioned domain, network ID, device kind, canonical SSH wire bytes, and WG bytes. Names and comments are not identity inputs; public SSH keys must be comment-free.

An SSH signature binds the WG public key but does not prove possession of its private key. The server calls `WgChallenge::begin`; the new laptop calls `answer_challenge`; the server consumes `PendingWgChallenge::verify`. The challenge expires within 300 seconds and binds the request, network, device, nonce, and ephemeral key. OpenSSL performs X25519 and HMAC-SHA256, and compares responses in constant time. `VerifiedEnrollment` cannot be deserialized or constructed by a caller. The caller authenticates the challenge channel and retains the single-use server state. The exchange runs automatically online when the new device first refreshes after claiming its invitation. It never requires the inviting device to possess the new WG private key; a CLI creating a client identity holds the new keys itself and answers the challenge in-process.

The CLI creates a single-use invitation that names the client; the new device claims it, which gives the server its signed request. A CLI creating a client identity redeems its own invitation in a temporary directory with freshly generated keys. The server persists an expiring pending entitlement keyed by issuer and pending ID, with the exact signed request, authenticated approving device, approved permissions, and absolute membership expiry. It returns `PendingApprovalProfile`, containing the public request, pending ID, issuer, entitlement deadline, snapshot, and server pins. The pending record stays outside active membership and supplies no WG peers, SQL access, management rights, or ordinary SSH access. Its lookup ID is not a bearer credential. The parent owns this pending HTTP/storage state.

`PendingApprovalProfile::validate_for` checks local keys, request/entitlement expiry, network binding, effective issuer, and matching server pins, including a mandatory public HTTPS certificate for the issuer. Authenticate the profile's transfer first. The new laptop reaches the narrowly scoped public HTTPS activation endpoint using that certificate as its trust anchor, before any WG membership exists. The endpoint issues a fresh short-lived challenge bound to the stored request and network. Challenge refresh after expiry or restart requires no new manual file and never extends the entitlement deadline. Do not embed a five-minute challenge as the only usable credential in a potentially long-lived approval file.

`validate_connection_for` checks identity and current server pins without extending admission deadlines. The CLI prunes expired pins that remain bound to historical server records and requires an effective issuer. After an approval expires, it requests an authenticated snapshot instead of starting admission. This recovers a committed membership after a lost response, even if the expired pending record was deleted. The server still rejects unknown, expired, or revoked members. The client validates the exact admitted request and preserves known revocations before saving the active profile.

At activation, the server uses the stored entitlement, never client-supplied permissions or an echoed profile snapshot. Check its deadline, exact request, cancellation state, and current approving authority. Verify the challenge and call `RegistrySnapshot::approve` against the current local snapshot, using activation time as `Approval.created_at` and preserving approved absolute expiry and rights. Serialize these checks with revocation and persist activation plus a stable retry result before consuming the entitlement. Return `NetworkPublicProfile` once admission is active; report OS reconciliation separately. A repeated successful activation retrieves the same result. Endpoint rate limits, durable command replay, server TLS, and one-time consumption are parent-owned.

`RegistrySnapshot::approve(verified, Approval)` returns an immutable `Member`; it does not write it. The trusted server serializes authorization and commit, checks stable command IDs, persists accepted records, and reconciles OS state. Only trusted agents can import `Member`, `Revocation`, and `Ack` records. Do not expose their deserializers as a client mutation API. `wg_verified` and `independent_root` are trusted server assertions, not applicant claims. Unverified key claims do not participate in effective membership or collision detection. Conflicting verified records and address collisions fail closed; identical duplicate delivery is safe.

`Permissions` is `Full` or `Deploy(scopes)`. `Permissions::default()` is `Deploy` with no scopes and grants nothing. `can_deploy` requires an exact canonical `app/env`. Only full members approve admissions, publish or read secret records, peer over WireGuard and receive SSH access. Deploy members release to their scopes and read only the non-secret database directory. Parent adapters must enforce the result on every RPC, upload, log, secret, and deployment operation.

A full member's SSH key opens the `tako` account (`SSH_USER`), which owns server state, the management Unix socket, and privileged helpers. That is full authority, not an unprivileged member shell. The parent must account for equivalent privileged Unix accounts or aliases in its OS account policy.

Ordinary admissions record the approving device. `effective_members(now)` admits a member when its approver was live, unrevoked and itself validly approved at the moment it approved. Revoking an approver later does not revoke the members it approved: revocation affects one device. Admission and revocation are not globally ordered; a partitioned server may still accept a denial from an already-revoked member. Accepted denials remain permanent after convergence, even when their actor is no longer effective.

Independent recovery authority has a separate entry point. `approve_independent_root` requires a server adapter to authenticate a local operator independently of network device grants, for example through a protected root console. It requires `independent_root = true`, `approved_by = None`, and full permissions. An ordinary RPC cannot invoke this operation. Operator-authenticated recovery works even when every full client has been revoked, but cannot revive banned keys. The operator's audit log records who authorized the independent root.

Existing immutable records cannot silently become independent; use fresh keys for replacement. Routine server retirement denies that server's identity, not admissions it merely wrote.

`plan_revocation` captures the target device and both key fingerprints, plus all known enforcement servers. Negative facts override stale membership and new identities that reuse either key. Persist the returned record before reporting durable acceptance. Apply WG removal, future SSH/login denial, session cancellation, and management denial before recording an `Ack`. This crate cannot perform or attest OS enforcement. The parent bounds input sizes without discarding historical revocations, owns synchronization with queued privileged work and distinguishes durable receipt from completed enforcement.

`revocation_progress` requires fresh authenticated readiness reports from reachable, successfully reconciled server agents. Remove a boot entry after failed enforcement or loss of readiness. It reports every captured server and later-admitted server without a matching current ACK as pending. Old ACKs, absent members, and server retirement never imply fencing. Restarts, failed enforcement, offline servers, and restore uncertainty remain visible. The parent must gate a newly admitted server on synchronization and reconciliation. No function claims that a local snapshot is globally current.

The IPv6 derivation uses `fd` plus 40 bits of SHA-256 over `tako-network-prefix-v1\0 || network_id`, then 80 bits over `tako-network-host-v1\0 || network_id || wg_public_key`. Inputs are raw bytes. `Member::allowed_ip()` returns only an exact `/128`. There is no allocation counter, central allocator, or primary server.

`NetworkPublicProfile` contains only the public request, registry snapshot, and exact effective server pins. `validate_for` checks local public-key ownership, admitted request identity, and server-pin consistency. It cannot authenticate a file's origin. Import only through authenticated transfer or a pinned server connection; a digest or certificate carried inside the same untrusted file is not a trust anchor. An absent HTTPS certificate in an active profile requires ordinary trusted certificate validation, never disabled verification. Pending activation profiles require the certificate. The parent must also bind import to the user's intended network when an unbound request was used.

On Unix, `save_new` traverses directories without symlinks, requires a caller-owned parent directory without group/other write permission, writes a fresh 0600 temporary file, fsyncs it, publishes with a non-replacing hard link, removes the temporary name, and fsyncs the directory. Existing files and symlinks cannot be replaced. `load` checks file type, ownership, exact permissions, link count, and a bounded file size. A crash between publication and temporary-link removal fails closed until the operator removes the orphan temporary link. A reported I/O failure after publication requires inspecting the path rather than overwriting it. Non-Unix platforms return `UnsupportedPlatform` until a secure platform store is supplied.

Private key objects have no `Debug` or serde implementation. Temporary serialized secrets use zeroizing buffers. `wireguard_private_key` explicitly exports a zeroizing value only for a trusted WireGuard configurator. Never put it in a public profile, CLI log, app environment, or process argument. `sign` permits SSHSIG authentication without exporting the SSH private key. `ssh_private_key()` returns `Result<Zeroizing<String>>` containing the device's unencrypted OpenSSH identity for standard `tako ssh`. Write it to an owner-only temporary 0600 identity file, pass only the file path to `ssh -i`, and remove the file after SSH exits, including failure paths. Never log the contents, include them in profiles, or pass them as process arguments. The CLI owns that temporary file's lifetime.

Run `cargo test -p tako-network --offline` and `cargo clippy -p tako-network --all-targets --offline -- -D warnings`. The tests cover real cryptographic proofs and Unix persistence, plus policy failures and partition scenarios over snapshots. They do not prove Raft failover, OS WireGuard enforcement, SSH session termination, or integrated CLI/server behavior; the parent owns those checks.

`ServerInfo` carries an optional `https_certificate_pem` string. It is bounded to `MAX_CERTIFICATE_PEM_BYTES`, 16 KiB, and parsed by OpenSSL as exactly one X.509 certificate; extra blocks/data and private keys are rejected. Public certificates are profile data, never CA private keys. `https_spki_fingerprint()` derives the HTTPS certificate's SHA-256 SPKI fingerprint. The optional `https_spki_sha256` field is only a consistency check and must match a supplied certificate; it is not a second authority. The parent can pass the public HTTPS PEM to `reqwest::Certificate::from_pem` and `ClientBuilder::add_root_certificate` without a custom TLS verifier. Generate the HTTPS certificate after device keys so its SANs cover the public endpoint IP and derived private WG IP. The parent verifies SANs, certificate purpose, validity, and TLS identity; parsing here does not establish those properties.
